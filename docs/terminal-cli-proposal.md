# 终端 CLI 控制方案（讨论稿，未实现）

现有终端由原生桌面进程持有，窗口收起后仍在托盘运行。CLI 可以作为短连接客户端访问这个进程，无需再创建一个终端服务或迁移进程。当前生产版本没有这些命令；验收构建中的 MyGo automation 接口只用于测试，不能当作已发布的控制接口。

建议先提供三个基本动作，再考虑 Agent 之间的任务协调：

```text
cyrene sessions list --json
cyrene terminal read --id <instance:session> --tail 200
cyrene terminal paste --id <instance:session> --stdin
cyrene terminal key --id <instance:session> Enter
```

列表返回明确的会话 ID、别名、分组、工作目录、启动配置、进程存活状态，以及所在画面/窗格。目录来自终端当前上报，不能保证未接入目录上报的 shell 会更新。会话 ID 带实例身份，避免应用重启后把旧 ID 路由到新进程。画面拆分或移动不改变会话 ID。

`read` 默认读取已渲染的终端文本，返回范围与截断信息。它不等于完整 Agent 对话或完整进程日志；如果需要增量事件，应单独设计游标和输出缓冲，而不是用反复截图或屏幕文字推断任务是否完成。

`paste` 默认只放入文本，不附加回车，沿用终端的粘贴语义。提交输入用独立且明确的 Enter 动作；Ctrl+C 等控制键也必须显式指定。终端前台可能是 shell、Agent、编辑器或确认弹框，因此接口称为“发送输入”，不能声称每次都执行了 shell 命令。返回值区分“已接受输入”和“子任务执行完成”。

Windows 可采用当前用户可访问的命名管道，其他平台使用本地套接字；请求在 UI 线程校验目标并取快照，通过现有终端对象发送输入，不从 IPC 工作线程直接修改工作区。CLI 未找到运行实例时返回错误，不悄悄新开应用。第一版只提供本机连接，可按调用者限制允许访问的会话及读写能力。

其他 Agent 可以通过自身的 shell/tool 执行 CLI，也可以配一个描述命令和 JSON 的 Skill。初期不必增加 MCP。调用者应使用返回的明确 ID，避免按标题模糊匹配或把分组里所有终端一起广播。后续若要等待任务完成、自动认领工作或协调多个 Agent，需要另加任务协议，不能仅靠终端输入输出判断。

本次只讨论此设计；没有启用 IPC 服务、发送输入的 CLI 或 Agent 控制权限。
